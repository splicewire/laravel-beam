# Merge strategies

`beam.particle.merge` holds the strategies a **composite backing** uses to read several sources as one
list. A composite backing has *arms* (a tickets table, an emails table, a read model) and names a
merge strategy by handle. The strategy takes one page from each arm and returns one merged, paged
stream. Each entry is a `MergeStrategy`, registered under its handle.

## The default: `ordered`

Beam registers one strategy, `ordered`. It merges the arms by a shared sort key, newest first. Its
cursor remembers where each arm stopped, so page two resumes every source exactly where page one
left off instead of re-reading everything. The rule for your arms is one sentence: every arm pages
itself by the same sort key, descending.

A composite asks for it by handle:

```php
protected function mergeHandle(): string
{
    return 'ordered';
}
```

`ordered` is registered as part of the registry itself, not by a provider, so it is there even where
Beam's service provider never booted.

## Adding a strategy

A package with a different way of merging, such as relevance-ranked search across sources, registers
its own handle from its own provider, and its composites name that handle:

```php
use Splicewire\Beam\Particle\Backing\Merge\MergeStrategyRegistry;

$this->app->make(MergeStrategyRegistry::class)->register('ranked', new RankedMergeStrategy);
```

Beam doesn't need to know the package exists. Entries are shared instances, because a strategy holds
no state of its own.

## Replacing the default

The policy is **supersede**, so your application can register its own `ordered`, and every composite
that names `ordered` uses yours. The displaced default stays readable as a superseded entry.

# Flows

`beam.flows` holds the **flows** every installed package declares: a named, host-visible capability
path — `account.security.passkeys`, `auth.register`, `teams.team-of-one` — that a browser test
proves, a `BEAM.md` Deviation may switch off, and the doctor reasons about. Each entry is a
`FlowDeclaration`, filed under its own flow key. A package ships one static `DeclaresFlows` class and
its provider declares it; the first segment of a key is its **surface** (`account`, `auth`, `teams`),
itself a declared flow with no entry routes.

## What a flow declaration carries

A `FlowDeclaration` is a plain readonly value object — data and class-strings only — with six
author-typed fields, none defaulted (an omission and a decision must not be spelled the same):

- **`key`**: `surface[.flow[.subflow…]]`, each segment `[a-z][a-z0-9]*(-[a-z0-9]+)*`. The parent is
  the key minus its last segment; a surface (one segment) has none.
- **`label`**: an English literal. Its text key is derived, `<ns>::flows.<key with dots as '/'>.label`.
- **`routes`**: entry route **names** (`[]` for a surface, or a page the host renders).
- **`gate`**: a `class-string<FlowGate>`; `Gates\AlwaysOn::class` when there is no runtime switch.
- **`checkpoint`**: a nullable `class-string` (ticket 04's Checkpoint contract; `null` until ticket 16
  ships checkpoints).
- **`roles`**: the demo-subject roles this flow is verified for; `[]` is a guest flow.

The **declaring package** is not a field: it is the registrant, recorded by the catalog when the
package's provider calls `declare()` under its `ScopesRegistrant` scope.

## Declaring your flows

```php
use Splicewire\Beam\Flows\{DeclaresFlows, FlowDeclaration, ListsFlows};
use Splicewire\Beam\Flows\Gates\AlwaysOn;

final class AccountFlows implements DeclaresFlows
{
    use ListsFlows; // adds static flow($key), safe to call before Laravel boots

    public static function flows(): array
    {
        return [
            new FlowDeclaration('account', 'Account', [], AlwaysOn::class, null, []),
            // …
        ];
    }
}

// in your provider, inside its ScopesRegistrant scope:
$this->app->make(\Splicewire\Beam\Flows\FlowCatalog::class)->declare(AccountFlows::class);
```

## The gate answers for the host, now

A `FlowGate` is resolved from the container and answers one `FlowState` — `On`, `Off` or `Absent` —
for the host, with no actor and no role. `Absent` is the structural third answer: a host that has
declared a whole capability estate absent, or has not wired the feature, has no flow to switch. A gate
must not throw; the doctor reports a throw as a finding. A flow with no switch names `AlwaysOn`.

## Recording baselines: the host pass and the package pass

`splicewire:beam:browser:record-baselines` promotes a fresh Browser-suite capture into the committed
screenshot baseline for each declared flow (record host only — see the command's own docblock for the
determinism gate). It runs in two shapes, and the difference is which flows it commits and *where*
(browser-journeys PRD, tickets 25 and 26):

- **The host pass** — no `--for`/`--into`. Every declared flow with a fresh capture is committed under
  the **running app's** `tests/Browser/screenshots`, git drift reported in the app repo. This is the
  historic behaviour and is byte-for-byte unchanged; the host reference pass relies on it.
- **A package pass** — `--for=<vendor/name> --into=<repo>`. Only flows whose **catalog registrant** is
  that package are committed (every other declared flow is listed as skipped and never written), into
  **that package's own** checkout, git drift reported there. Fresh captures are still read from the
  running app — a package proves its own flows against the host that ran them.

A flow key two packages both declare **supersedes** (`beam.flows` is a supersede-key registry): the
later registrant wins, and the earlier declaration is displaced into supersession history, which
`keysBy()` never reads. So `keysBy()` answers the shared key for the **winner** only — `--for=<winner>`
commits it into the winner's repo, and `--for=<the superseded declarer>` lists it as skipped and never
writes it. The baseline lands in exactly one repo, never duplicated and never tie-broken by this
command (the catalog already resolved the winner); the doctor reports the supersession, naming the
winner and the displaced registrant. A package that **extends** another's surface should register a
sibling/child key at the correct seam, not re-declare the same key (owner ruling 2026-11-24). The
three fail-closed guards (`--into` without `--for`, a `--into` path that is not an existing directory,
a `--for` package that declares no flow) refuse rather than write the wrong — or no — baselines.

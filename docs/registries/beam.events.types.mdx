# Event types

`beam.events.types` is the catalog of **publishable events**: the names a tenant's webhook can
subscribe to, and what each delivery is about. `GET /hooks/events` lists it, and a subscribe call
looks names up in it. Each entry is an `EventType`, filed under its own name. Because the catalog is
declared rather than inferred from what fires, a client can see the whole vocabulary before any
event has happened.

## Naming an event

A name is `{resource key}.{verb phrase}`: `compositions.render.completed` is the `compositions`
resource plus the verb phrase `render.completed`. The resource key is always the first segment and
is spelled exactly as the resource registry spells it, plural included. That is what lets
`GET /hooks/events?resource=compositions` return a resource's events by segment. A `composition`
filter never picks up `compositions.*`.

## Declaring one

Register from your provider. [Splicewire](https://splicewire.com/) declares its provisioning event
like this:

```php
use Splicewire\Beam\Events\EventType;
use Splicewire\Beam\Events\EventTypeRegistry;

$this->app->booted(function () {
    $this->app->make(EventTypeRegistry::class)->register(
        new EventType(
            name: 'tenants.provisioned',
            subject: Tenant::class,
            description: 'A brokered child tenant reached a terminal provisioning state.',
        ),
        null,
        self::class,
    );
});
```

`subject` is the model a delivery is about, the thing a subscriber filters on. `payload` names the
Data class for the wire body, and can stay null until you write one. You can also put
`#[BeamEvent('tenants.provisioned', subject: Tenant::class)]` on an event class and list the class
in `beam.core.events.classes`, or its directory in `beam.core.events.discover_paths`. The attribute
is repeatable, so one class can publish several names, and it calls the same `register()`.

## What registration checks

Registration is the only place an event is validated, and each of these throws:

- the name parses as a key and has at least two segments;
- it has a `subject`, unless it explicitly says `subjectless: true`;
- the name isn't already taken.

That last rule is the
[**duplicate-key policy**](/beam/docs/foundations/registries#key-policies), **reject**. Two
providers claiming one event name means two teams think they own one wire contract, and no
subscriber is safe with "the later one wins", so boot fails loudly instead.

<Callout type="note" title="One advisory check">

Whether the name's first segment is a resource this host actually has is only advised on:
`splicewire:beam:doctor` reports a dead prefix as `events.catalog-prefix`, and the event is still
registered. Firing an event that isn't in the catalog never fails; it simply finds no subscribers.

</Callout>

## What ships

Beam fills the catalog with `hooks.disabled` and `hooks.verified`, and with one
`{resource}.persisted` event for every writable particle resource that has a single model class.
Hosts get those with no config at all.

The `{resource}.persisted` entries are catalog-only for now. A hook can subscribe to one, but
nothing delivers it yet, and each entry's description says so. To react to a write inside your
application, listen for `BeamParticlePersisted`. Of the events Beam ships, only the two `hooks.*`
ones are delivered.

## What a subscriber reads, captured

This example declares one more `hooks.*` event, then lists the catalog the way
`GET /hooks/events?resource=hooks` does: one descriptor per name, with the resource key and the
verb phrase split off, and the subject published as its morph alias (`hook`), never the model's
class name. The first three entries are the ones Beam ships. The JSON is the real output of the
PHP beside it, captured by the package and re-checked by its test suite.

<DataExample source="docs/registries/examples/beam.events.types/catalog-entry.php">

```php
use Splicewire\Beam\Events\EventType;
use Splicewire\Beam\Events\EventTypeRegistry;
use Splicewire\Beam\Webhooks\Data\EventTypeDescriptorData;

// A package declares one publishable event beside the ones Beam ships.
$catalog = app(EventTypeRegistry::class)->register(new EventType(
    name: 'hooks.paused',
    subject: Splicewire\Beam\Models\Hook::class,
    description: 'A hook stopped delivering until an operator resumes it.',
), null, 'acme/hooks');

// The catalog as `GET /hooks/events?resource=hooks` lists it: one descriptor per name, the resource split off.
return array_map(
    fn (EventType $type) => EventTypeDescriptorData::fromEventType($type),
    $catalog->withPrefix('hooks'),
);
```

# Doctor audits

`beam.doctor.audits` is the list of readiness checks that `splicewire:beam:doctor` runs after its
built-in ones. Each Beam package, and the host application itself, adds its own checks here, so
one command reports on the whole installed stack instead of each package shipping its own
`*:doctor`. Each entry is a `DoctorRegistration` from
[`rushing/laravel-doctor`](https://github.com/stephenr85/laravel-doctor): the package name, the
audit class, whether it gates the run, and an order.

## Registering an audit

An audit is any class implementing `Rushing\Doctor\DoctorAudit`, whose `run()` returns a list of
`Finding`s (pass, warn, fail or inconclusive). Generate one rather than writing it by hand:

```bash
php artisan doctor:make:audit PublishGateCoverage
php artisan doctor:make:audit PublishGateCoverage --package-path=../packages/acme/laravel-widgets
```

The generator comes with [`rushing/laravel-doctor`](https://github.com/stephenr85/laravel-doctor), so
every Beam host already has it. It writes the audit under your `Doctor` namespace, with a `CHECK` name
and a `run()` that reports an empty population as inconclusive rather than clean. It also writes a
test in the runner your project already uses. It targets your app unless `--package-path` names a
package root; that package's `composer.json` decides the namespace. Last, it prints the line that
registers the audit. Add that line to your provider's `boot()`:

```php
use Acme\Widgets\Doctor\PublishGateCoverageAudit;
use Splicewire\Beam\Doctor\BeamDoctorManifest;

if ($this->app->bound(BeamDoctorManifest::class)) {
    $this->app->make(BeamDoctorManifest::class)->register('acme/laravel-widgets', PublishGateCoverageAudit::class);
}
```

The `bound()` guard lets the package still boot against an older Beam. A host application registers
the same way from its own `AppServiceProvider`, and the generator prints that line without the guard:
the manifest is bound before any provider boots, and the doctor reads it when the command runs. Pass
`--suggests-operations` when the audit can also name its fix. The class then implements
`rushing/laravel-surgeon`'s `SuggestsOperations` too, pairing each finding with the operation that
repairs it.

Two named arguments shape how a check behaves:

- **`gate: true`** lets a failing finding turn the run red. By default an audit is advisory: its
  findings are printed but never change the exit code. `--floor=warn` makes a gating audit's
  warnings fail the run too.
- **`order:`** places the audit in the run. Lower runs first, and the default is `100`.

## What a duplicate means here

Entries are keyed by **audit class**, not by package, because one package usually ships several
audits. The [**duplicate-key policy**](/beam/docs/foundations/registries#key-policies) is
**supersede**: registering the same class again replaces the earlier registration, so a provider
that boots twice, as in a test harness, doesn't run its audit twice.

## What isn't here

Beam's oldest core checks are built into the doctor command itself and run first; they aren't
entries in this registry. Beam's newer audits, such as its house-style and bypass checks, are
registered here like everyone else's, under `splicewire/laravel-beam`.
